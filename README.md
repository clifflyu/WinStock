# WinStock

一个轻量的 A 股日线数据初始化工具。它会建立 A 股证券清单，并分批下载从 `2024-01-01` 至当前日期的前复权日 K，写入本地 SQLite。

## 使用

无需安装第三方包，要求 Python 3.10+。

```bash
# 建立清单并下载日 K（默认数据库：./data/winstock.db）
python -m winstocker init

# 限制并发、分批大小或更改起始日期
python -m winstocker init --start 2024-01-01 --batch-size 100 --workers 6

# 仅刷新 A 股清单
python -m winstocker list

# 查看下载进度、行数和失败记录
python -m winstocker status

# 每个交易日收盘后执行：重抓最后一天并补齐新交易日，不重复全量下载
python -m winstocker update

# 每次回测前审计数据覆盖、失败任务和数据库完整性
python -m winstocker audit

# 运行单股日频双均线研究回测（昨日收盘生成信号，次日开盘成交）
python -m winstocker backtest 600000 --fast 20 --slow 60

# 在指定股票池中，按 20 日动量选前 3 只，每 20 个交易日调仓
python -m winstocker rotation --symbols 600000,000001,300750,600519 --top-n 3

# 保存包含参数、结果和风险提示的可复现研究报告
python -m winstocker rotation --symbols 600000,000001,300750,600519 --output reports/momentum.json

# 将前 70% 历史作为训练段，后 30% 作为未参与评估的验证段
python -m winstocker validate --symbols 600000,000001,300750,600519 --output reports/validation.json

# 与沪深 300 买入持有比较，检查主动策略是否创造超额收益
python -m winstocker compare --symbols 600000,000001,300750,600519 --benchmark 000300
```

数据库路径可用 `--db /path/to/file.db` 指定。首次使用执行 `init`；此后每个交易日收盘后执行 `update`。`update` 会重抓最新已存交易日以修订可能的源端更正，再补齐新交易日，而非重下全量历史。证券和日 K 均以主键 UPSERT，失败的证券会记录在 `download_failures` 表中，下一次更新会重试。

## 数据范围与表

- 清单范围：沪市 A 股、深市 A 股、创业板、科创板；不包含 B 股、ETF、指数和港股。
- `securities`：证券代码、市场、名称、状态和清单更新时间。
- `daily_kline`：**视图**，交易日、开高低收、成交量、成交额、振幅、涨跌幅和换手率。
- `kline`：日 K 的实际存储表，`daily_kline` 由它和 `securities` 联接而成。
- `download_failures`：最近一次下载失败信息。

### 存储布局

日 K 是唯一的大表，做了三项压缩，全量 5225 只股票约 173 MB：

1. `kline` 用 `WITHOUT ROWID`，主键不再是独立的索引树，省掉一份主键的重复存储。
2. 证券代码存成指向 `securities.id` 的整数外键，不再逐行重复 6 字节字符串。
3. 十个数值列按定点整数存储（价格 ×1000、量与额 ×100、百分比 ×1000），读取时由视图除回小数。

`daily_kline` 视图还原了改动前的全部列名与小数口径，**查询写法不用改**：

```sql
SELECT trade_date, close FROM daily_kline WHERE symbol = '600000' AND trade_date >= '2026-01-01';
```

只有 `change_pct`、`amplitude` 这类推导值会保留三位小数（源数据本身只有两位），其余列无损。若要写入，请直接操作 `kline` 表。

打开旧布局的库时会自动就地迁移，无需重新下载；迁移过程可在 `status` 或 `init` 时触发。

## 数据来源

- **证券清单**：东方财富延时行情接口（`push2delay.eastmoney.com`）。东方财富的 `push2`/`push2his` 主机对海外与机房 IP 会直接断连（TCP 连通、TLS 握手正常，但一发 API 请求就被切断且不返回任何字节），延时主机不受影响。
- **日 K**：腾讯行情接口（`proxy.finance.qq.com`），前复权口径与东方财富的 `fqt=1` 一致。

换手率与成交额由腾讯直接返回，成交额原始单位为万元，入库前换算成元。

**成交量统一为手。** 腾讯对科创板（代码 `688`/`689`）返回的成交量单位是**股**，其余板块是手，两者相差 100 倍；入库前会把科创板的成交量折算成手，保证 `volume` 列全库同单位。这条已用新浪逐股核对：主板与创业板的腾讯值 = 新浪值 ÷ 100，科创板两者完全相等。

涨跌幅、振幅、涨跌额需要推导。推导优先使用**不复权**序列（该序列在非除权日与交易所公布口径完全一致），只在复权因子跳变的除权日改用前复权比值，否则跨不过除权缺口。之所以不能直接用前复权价推导：前复权价被压缩且只保留两位小数，求比值会放大舍入误差，实测最大偏差 0.49 个百分点、约四分之一交易日偏差超过 0.1。因此每只股票会同时抓取前复权与不复权两份序列，请求量约为股票数的两倍。

两份序列都按「以结束日期为起点、每次 640 根反向翻页」取满区间，区间首根的前收盘价由翻页多取的若干根提供，这些额外数据不会入库。

两个接口都存在访问频率限制；网络不稳时可降低 `--workers`，然后重新运行同一条 `init` 命令。

运行回测前先执行 `audit`。若出现无日线证券、落后数据或待重试失败，先修复或排除相应标的；不要把缺失数据造成的回测结果当作策略优势。

## 日频研究回测

`backtest` 是用来验证研究想法的首个闭环：单股、仅做多、全仓/空仓双均线策略。订单使用前一交易日收盘前可获得的均线信号，并在下一交易日开盘以滑点成交，因此不会用到当日收盘价来决定当日交易。

默认假设为佣金万三（最低 5 元）、卖出印花税万五、单边滑点 5bp，均可通过命令行调整。订单按 100 股整手买入，并在开盘触及常规涨停/跌停时分别阻止买入/卖出；创业板与科创板按 20% 阈值，其余按 10%。新股前五日无涨跌停、历史 ST 标记、停复牌、分红现金流和真实盘口成交仍不在当前数据范围内，因此结果只能用于研究，不能视作实盘收益承诺。

`rotation` 在用户明确提供的股票池中，按前一日收盘可见的过去 `lookback` 日收益率选出前 `top-n` 只，并在当日开盘调仓。它不会默认跑全市场：当前库保存的是当前证券清单，用它构造历史全市场股票池会有幸存者偏差。股票池也应在研究前按当时可交易的成分、ST 状态和流动性条件固化。

轮动、验证和基准比较默认要求至少 250 个历史交易日，且近 `lookback` 日平均成交额不少于 2,000 万元。可用 `--min-history` 和 `--min-avg-amount` 调整；默认门槛是为了避免次新股、停牌股票或低流动性股票让回测成交假设失真。

给 `backtest` 或 `rotation` 传入 `--output reports/name.json` 会保存机器可读的研究档案：策略参数、数据区间、交易成本、结果和风险提示。报告会明确标记成交次数不足、回撤超过 20%、亏损区间或跌停无法卖出的情况；它不会给任何策略标注“保证盈利”。

`validate` 会按时间顺序切分训练段与样本外验证段，两段独立建仓、独立回测。验证段不是未来预测，但它没有参与同一次结果评估，能更早暴露只适合历史行情的策略。验证段为负、交易样本太少或明显弱于训练段时，不应进入模拟交易。

`compare` 默认以沪深 300（000300）价格指数的同期买入持有收益为基准，并输出策略超额收益。指数价格口径不含基金申赎成本与股息再投资，故只用作基础市场比较；未跑赢基准的策略不应作为主动交易候选。
