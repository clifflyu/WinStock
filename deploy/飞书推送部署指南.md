# 飞书推送部署指南

部署完成后，你**不需要再执行任何命令**。每天北京时间 19:30，服务器会自动：

1. 更新全 A 股日 K 数据
2. 检查数据健康
3. 按动量筛出候选池 Top 10
4. 把结果推成一张飞书卡片

下面是首次部署要做的六步。命令按顺序复制粘贴即可。

---

## 前提条件

- 一台**常开**的 Linux 服务器（带 systemd）。笔记本、WSL、会关机的机器都不合适——关机期间任务不会执行。
- Python 3.10 或更高版本。
- 服务器能访问行情接口和 `open.feishu.cn`。

---

## 第一步：前置检查

```bash
python3 -V
systemctl --version | head -1
curl -sI -m 10 https://open.feishu.cn/ | head -1
curl -sI -m 10 https://proxy.finance.qq.com/ | head -1
timedatectl | head -4
```

**预期结果**：

| 命令 | 期望 | 不符合怎么办 |
|---|---|---|
| `python3 -V` | `Python 3.10.x` 或更高 | 版本过低：`apt install python3.11` 或换台机器 |
| `systemctl --version` | 有版本号输出 | 没有 systemd 的机器（如容器）不能用本方案 |
| 飞书 `curl` | `HTTP/1.1 404` | **404 是正常的**，说明连得通；若是超时或连接被拒，检查防火墙 |
| 腾讯行情 `curl` | `HTTP/1.1 200` 或 `301/302` | 连不上则数据下载会失败，检查出口网络 |
| `timedatectl` | 显示时间与时区 | 时钟必须准：签名校验依赖时间戳，误差超过 1 小时会被飞书拒绝 |

---

## 第二步：取代码

```bash
git clone https://github.com/clifflyu/WinStock.git /opt/winstock
cd /opt/winstock
```

若服务器没有 git：`apt install git`（Debian/Ubuntu）或 `yum install git`（CentOS/RHEL）。

---

## 第三步：准备数据

**两条路线选一条。** 已经有数据库文件的用 B，全新服务器用 A。

### 路线 A：让服务器自己下载（推荐，无需传文件）

```bash
cd /opt/winstock
python3 -m winstocker init
```

从 2024-01-01 下载到昨天，约 5200 只股票，**耗时 30–60 分钟**。中途中断可直接重跑，已下载的不会重复下载。

### 路线 B：从已有机器复制数据库（快，几分钟）

在**已有数据的那台机器**上执行：

```bash
# 先在服务器上建好目录
ssh 你的服务器 'mkdir -p /opt/winstock/data'

# 再传过去（约 192 MB）
rsync -avP data/winstock.db 你的服务器:/opt/winstock/data/
```

### 无论哪条路线，都要验证

```bash
cd /opt/winstock
python3 -m winstocker status
python3 -m winstocker audit
```

**通过标准**：`status` 显示日 K 条数在百万级；`audit` 第一行是「数据审计：通过」，最后一行「下载失败待重试：0」。

如果显示「需检查」，**先不要继续**，把输出发给我。

---

## 第四步：配置飞书 Webhook

### 4.1 在飞书里拿地址

建一个群（只有你自己也行）→ 点群名称进**群设置** → **群机器人** → **添加机器人** → 选**自定义机器人** → 起个名字 → 复制 **Webhook 地址**。

> 如果机器人设置里让你选安全策略，建议先选**「签名校验」并复制密钥**（比关键词和 IP 白名单都省事），或者**什么都不开**。**不建议选「自定义关键词」**——卡片正文必须包含那个词才发得出去，容易踩坑。

### 4.2 写到服务器上

把下面的 `https://...` 换成你刚复制的地址：

```bash
install -d -m 0750 /etc/winstock
cat > /etc/winstock/notify.env <<'EOF'
WINSTOCK_FEISHU_WEBHOOK=https://open.feishu.cn/open-apis/bot/v2/hook/换成你的地址
WINSTOCK_FEISHU_SECRET=
EOF
chmod 600 /etc/winstock/notify.env
```

开了**签名校验**的话，把密钥填到 `WINSTOCK_FEISHU_SECRET=` 后面；没开就保持留空。

> **三个必须注意的点，踩中任何一个都会发不出去：**
> 1. **等号右边不要加引号。** systemd 不解析引号，`="https://..."` 会把引号当成地址的一部分。
> 2. **不要写行尾注释。** `KEY=value  # 说明` 会把 `# 说明` 也算进值里。
> 3. 这个文件**含密钥**，别提交到 git，别改成 644。

---

## 第五步：安装定时任务

```bash
cd /opt/winstock
sudo ./deploy/install-systemd.sh
```

脚本会自动识别 Python 路径和数据库位置，创建 `/etc/winstock/notify.env`（若不存在），装上 systemd 服务与定时器并立即启用。

结束时若看到 `⚠ 尚未配置飞书 Webhook`，说明第四步没生效，回去检查文件内容。

---

## 第六步：验证

### 快速验证（几秒钟）

先确认飞书链路通：

```bash
sudo bash -c 'set -a; . /etc/winstock/notify.env; set +a; cd /opt/winstock; python3 -m winstocker notify --test'
```

看到「已发送，请查看飞书群」后，去飞书确认收到一张蓝色的**配置自检**卡片。

### 完整验证（几分钟）

跑一次完整的真实流程：

```bash
sudo systemctl start winstock-update.service
journalctl -u winstock-update.service -n 50 --no-pager
```

这会真实更新数据并推送一张绿色播报卡片。跑完后确认：

```bash
systemctl list-timers winstock-update.timer --all
```

应当能看到 `NEXT` 列是明天 19:30。

**到这里就完成了，之后不用再管。**

---

## 退出码含义

`daily` 用退出码区分失败面，`systemctl status` 和 journal 里能看到：

| 码 | 含义 | 你要做什么 |
|---|---|---|
| 0 | 数据更新成功，卡片已送达 | 无 |
| 1 | 数据更新失败，但**红色卡片已送达** | 看卡片上的失败原因 |
| 2 | 数据正常，但**卡片发送失败**（你没收到消息） | 查 journal 里的飞书报错 |
| 3 | 数据失败**且**通知失败 | 最严重：查 journal |

## 故障排查

### 收不到消息

**没有消息本身就是信号。** 每天 19:30 之后（通常几分钟内）没收到卡片，就是出问题了——先去查日志：

```bash
journalctl -u winstock-update.service -n 100 --no-pager
systemctl status winstock-update.service --no-pager
```

### 飞书报错对照

| 报错 | 原因 | 解决 |
|---|---|---|
| `code=19021` 签名失败 | 密钥不对，**或服务器时钟不准** | 核对 `WINSTOCK_FEISHU_SECRET`；`timedatectl` 检查时钟；开了签名校验却没填密钥也会报这个 |
| `code=19022` IP 不在白名单 | 机器人开了 IP 白名单 | 用 `curl -s ifconfig.me` 查服务器出口 IP，加进机器人白名单 |
| `code=19024` 关键词不匹配 | 机器人开了「自定义关键词」 | 要么把关键词改成一个会稳定出现在卡片里的词（如 `WinStock`），要么去掉关键词策略改用签名校验 |
| `code=9499` 请求体格式错误 | `notify.env` 里的值带了引号或多余字符 | 按第四步的「三个注意点」检查 |
| `未配置飞书 Webhook 地址` | 环境变量没读到 | 确认 `/etc/winstock/notify.env` 存在且 `WINSTOCK_FEISHU_WEBHOOK=` 后面有值；改完要 `sudo systemctl restart` 不适用，直接重跑服务即可 |

### 卡片颜色

| 颜色 | 含义 |
|---|---|
| 🟢 绿 | 一切正常 |
| 🟠 橙 | 数据能读到，但审计有缺陷（卡片上会列出具体原因），**此时不要直接相信回测结果** |
| 🔴 红 | 数据更新失败，或有更新但读不了库。卡片上会写明原因 |

### 卡片到达时间不固定

19:30 是**任务启动**时间，不是送达时间。正常几分钟内送达；如果当天触发了全历史重抓（检测到前复权尺度漂移时），可能跑 20–60 分钟，卡片会晚到。这是正常的，不要以为卡住了。

## 日常维护

**不需要做任何事。** 每天看飞书即可。

偶尔会用到：

```bash
# 看今天为什么失败
journalctl -u winstock-update.service -n 100 --no-pager

# 手动跑一次（不等到 19:30）
sudo systemctl start winstock-update.service

# 暂停每日推送
sudo systemctl disable --now winstock-update.timer

# 恢复
sudo systemctl enable --now winstock-update.timer

# 改推送内容里的候选数量（默认 10）
sudo systemctl edit winstock-update.service   # 在 [Service] 段加：
# ExecStart=
# ExecStart=/bin/bash -lc 'exec "$WINSTOCK_PYTHON" -m winstocker --db "$WINSTOCK_DB" daily --top-n 5'
```

> 注意：`--top-n` 只改变卡片上显示的数量。`update` 内部固化的候选快照始终是 10 只——这样历史记录的口径不会因为推送设置变化而漂移。
